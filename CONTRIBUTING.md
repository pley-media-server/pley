# Contributing

[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) says how Pley is built and
tested, and [AGENTS.md](AGENTS.md) the rules every change keeps: the
checks to run, licensing, security, and how commits read.

## Bugs, ideas and questions

Bugs go in issues. Feature requests are best started in
[Discussions → Ideas](https://github.com/pley-media-server/pley/discussions/categories/ideas),
where others can vote for them, though a small, clear one can be an issue;
questions go in [Q&A](https://github.com/pley-media-server/pley/discussions/categories/q-a)
([SUPPORT.md](SUPPORT.md)). An idea is easier to take on once people have
voted for it and said what they'd use it for, so a large change starts there
or in an issue before a pull request.

## The license of a contribution

Pley is under the GNU Affero General Public License, version 3 only
([LICENSE](LICENSE), [LICENSING.md](LICENSING.md)), and what you
contribute comes under it too (`AGPL-3.0-only`). The Kodi add-on
(`apps/kodi`) is the exception: contributions to it come under its own
license, the GPL version 2 or later.

Opening a pull request confirms that you wrote what it contains, or have
the right to contribute it under these licenses.
